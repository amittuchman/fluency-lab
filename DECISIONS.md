# Decisions

Non-obvious choices, newest last. Each entry: what, and why.

## Setup

1. **Node 24 LTS installed via winget** (approved by the user). Node was not on the machine.
2. **TypeScript pinned to 6.0.** TS 7 is current, but typescript-eslint supports `<6.1`.
3. **`resolve.preserveSymlinks: true` in vite.config.ts.** The project sits in OneDrive, where every file is a
   reparse point. Rolldown's resolver treats them like symlinks and could not resolve any package without it.
4. **HashRouter + `base: './'`.** The build works from any sub-path (GitHub Pages) and offline without
   server rewrite rules.
5. **Noto Sans Hebrew is bundled** (fontsource), not loaded from Google Fonts, so Hebrew renders offline.
6. **PWA icons are generated by a tiny script** (`npm run icons`) with no image dependency.

## Data and scheduling

7. **Card content hash = what the card asks.** E.g. `recog` hashes term + definition. Adding a Hebrew gloss
   or an example does not reset `recog`; changing the definition does. Only cards whose hash changes restart
   their schedule when a note is edited.
8. **Templates that stop applying are deleted** (e.g. removing the only example deletes `cloze-use`). Their
   review logs stay for stats.
9. **Unlock chain uses the templates that exist.** If `cloze-use` is skipped (no example containing the term),
   `produce` is step 2 and needs the first threshold (2 days).
10. **Max interval 365 days is enforced in our wrapper.** ts-fsrs keeps Easy > Good > Hard by ≥1 day,
    which can push Easy past `maximum_interval`.
11. **Learning cards: 20-minute learn-ahead.** A card in a learning step (1m/10m) counts as due only when it is
    due within 20 minutes (Anki's default). Review cards count as due any time before the day rollover.
    Within a session, Again/learning cards come back 3 cards later.
12. **New cards rotate across types** before the daily limit is applied, so 10 new cards are not 10 vocab
    cards in a row. Reviews keep most-overdue-first, then a greedy interleave by type and tag.
13. **Siblings are buried until the next study day** (`buriedUntil`), not just within one session, so a second
    session the same day doesn't show the sibling either. Undo un-buries.
14. **Undo works on the current session's reviews** and restores the full card snapshot stored in the log
    (plus un-burying / re-locking what that review changed).
15. **`correct` in the log = grade > 1.** The checker suggests a grade; the user's final grade is the truth
    (e.g. a valid alternative phrasing graded Good counts as correct).
16. **Leeches are flagged, not auto-suspended** (lapses ≥ 6). The banner offers Edit / Suspend.
17. **Trash is purged automatically after 30 days** on app start. The delete confirmation says so.
18. **Duplicate import with "Update existing"** overwrites the fields, merges tags, and moves the note into the
    new package (that is the material about to be studied). Its cards follow rule 7.

## Answer checking

19. **Punctuation at word edges is ignored everywhere**, not only at the end. This is spoken English; a comma
    should never fail an answer. Apostrophes and hyphens inside words still count.
20. **Typo tolerance (Levenshtein ≤ 1, words of 5+ letters) is on for vocab and sentence cards**, off for
    fix / tense / natural / cloze.
21. **Cloze numbering is the order of appearance** (`{{…}}` #1, #2, …); no `c1::` syntax.
22. **The brief's cloze example `{{raised//has raised::raise}} rates last week` is ungrammatical** ("has raised"
    can't take "last week"). Docs and samples use `{{raised//put up::raise}}` instead.

## Templates

23. **`recall-full` without a Hebrew gloss prompts with first letters** ("T t i a c a i l.") until audio exists
    (Phase 4), then audio becomes the prompt.
24. **The conjugator was built in Phase 2**, because `tense-choose` needs it for distractors. It infers the
    subject's person from the word before the verb (skipping adverbs) and checks that it can reproduce the
    reference answer; if not (negatives, questions, passives), the card falls back to typed input.
25. **`natural` → `upgrade` is checked strictly**, like the brief says; the diff shows how far off you were and you
    can override the grade when your version is also natural.

## Drill

26. **Ready = the last two answers to a card (any mode) were correct.** Stateless, computed from logs, so the
    home widget and the drill agree. A wrong answer resets the streak.
27. **The drill's card set is fixed when it starts.** Templates unlocked during the drill go to normal SRS.
28. **Drill order rotates across note types**, like new cards in the daily queue.
29. **"Drill again" (`?all=1`)** re-drills every card when the whole package is already ready.

## Quiz, leeches, weak spots (Phase 2)

30. **Quiz questions may use any auto-checkable template of a note, locked or not.** A quiz measures what
    you can produce, independent of where the card is in its unlock chain. `recog` (self-graded) is never used.
31. **Quiz misses go to the note's most advanced unlocked card** (due now). If the missed template is still
    locked, it stays locked: the quiz does not skip the unlock chain. "Put misses at the front" also sets a
    `priority` flag that puts those cards first in the next daily session (cleared after one review).
32. **Quiz timer is a total time limit.** When it runs out, the quiz ends; the score counts answered questions.
33. **Weak items** (quiz source) = notes with lapses or misses in the last 30 days, weakest first.
34. **Saving an edit clears a note's leech flags**; a card re-flags at 6 lapses and then every 4 more
    (10, 14, …), like Anki. Without this, a fixed leech would carry the flag forever.
35. **Weak Spots ranks tags by 30-day accuracy**, then by current lapses. "Drill this tag" uses the same
    mastery loop as the package drill.
36. **Stats "tense mastery"** = average over the tense's cards of min(1, stability / 21 days): it rises steadily
    with practice and reaches 100% when every card is mature.

## Changes requested after the Phase 2 review

37. **Package Drill ignores the unlock chain and the daily new-card limit.** A drill
    covers every non-suspended card of the package, locked ones included; drilling a locked card unlocks it so
    it continues in normal SRS. Drill answers don't consume the daily new/review budget either: the drill is
    extra work on top of the daily session. "Ready X/Y" counts all those cards.
38. **Default new cards per day: 25** (was 10).
39. **"Copy import template"** copies a blank block with one placeholder line per item type, ready to paste
    into the AI coach's instructions. If the clipboard is blocked, the template goes into the text box instead.

## Tense Lab (Phase 3)

40. **Clicking a grid cell drills that tense right away** (`?all=1`: Tense Lab drills always include every item,
    since tense practice is repetition, not a one-time mastery check). Cheat-sheets have their own section.
41. **Cheat-sheet edits are stored as overrides in the meta table**; "Reset to default" removes the override.
    They ride along in backups.
42. **Time-signal highlighting** uses the signal words of all 12 cheat-sheets (whole words, longest first), so
    editing a sheet's signals changes what gets highlighted. Only in Tense Lab drills; normal reviews stay plain.
43. **Tense tags (`#tense:…`) are hidden under study cards**: they would give the answer away.
44. **Perfect vs perfect continuous with a duration** ("for five years", "since 2020"): both are usually correct
    English. The multiple choice never offers the twin as a wrong option, and typing the twin in a fill card
    counts as "almost" (Hard) with an explanation instead of "wrong".
45. **Adverbs inside the verb phrase** ("had already doubled", "have just left") are handled by the conjugator:
    it matches without the adverb and puts the adverb into every option. Negatives, questions and passives still
    fall back to typed input.
46. **Sample fix:** "I have read that book three times" also allows the past simple in American English;
    the sample now says "three times so far", which only fits the present perfect.

## Audio and speech (Phase 4)

47. **New templates arrive through `TEMPLATE_VERSION` 2.** On the next start every existing note gets its
    `dictation` (vocab) or `speak` (sentence) card, locked at the end of its unlock chain.
48. **Audio before the reveal only when audio is the question** (dictation, "listen then type", the shown term on
    a recognition card). On every other card the Play button appears after the reveal: hearing a cloze sentence
    would give the answer away. `R` replays.
49. **iOS needs a user gesture for speech.** "Autoplay on reveal" speaks inside the click/key handler that
    reveals the card. Dictation tries to play when the card appears; if the browser blocks that, the Play button
    is right there.
50. **Graceful fallbacks.** No TTS or no English voice: dictation becomes "produce the word", full recall uses
    first letters. No speech recognition: speaking cards become "say it aloud, then check" (self-graded), and the
    Speak screen is hidden from navigation.
51. **Speech scoring:** word-level similarity 2·LCS / (heard + target) over the best of 3 recognizer alternatives.
    "Correct" needs every word (≥ 0.98), so a skipped "on" is caught; ≥ 0.75 is "almost" (Hard). Results are
    labelled approximate, the user can override the grade, and "Type instead" is always offered.
52. **Speak mode is practice only**: shadowing and speaking recall don't log reviews or change scheduling.
53. **Quizzes skip dictation and speaking cards**, so a quiz can be taken silently (e.g. on a bus).

## Polish (Phase 5)

54. **Charts are hand-rolled SVG** (no chart library): a 14-day forecast (one series, so no legend) and a
    90-day heatmap on a single blue ramp, with separate light/dark steps checked with a palette validator.
    Both have a hover readout and a "Show as table" view.
55. **Screens load lazily** except Home and the study session. The first load got smaller; the service worker
    still precaches every chunk, so offline use is unchanged.
56. **Performance at 5,000 notes / 12,500 cards / 30,000 reviews:** every screen computation runs in
    5–30 ms (`src/data/perf.test.ts`); in a real browser the screens open in about 0.5–1.3 s (mostly reading
    IndexedDB). Two fixes came out of it: vocab parsing compiled a Unicode regex per term (5,000 lines took
    2.8 s, now ~0.1 s), and very large readiness/drill lookups now scan once instead of using `anyOf` with
    thousands of keys.
57. **The import box is `dir="ltr"`**, not `dir="auto"`: package text starts with `@type`, so it is LTR anyway,
    and `auto` doubled the layout cost of large pastes. Hebrew segments still render right-to-left inside it.
58. **Accessibility:** focus trap in dialogs, a skip link, one page title per screen, `lang="he"` on Hebrew
    text, `aria-live` on answer feedback and chart readouts, labelled controls, keyboard access throughout, and a
    `?` overlay listing every shortcut.
59. **E2E test runs on the installed Microsoft Edge** (`channel: 'msedge'`) so no browser download is needed.
60. **GitHub Pages deploy is a workflow file in the repo**; nothing is deployed until you push it to GitHub
    and switch Pages to "GitHub Actions" (see README).
61. **Restoring a backup counts as having a backup** from the file's export time, so the "never backed up"
    reminder doesn't appear right after a restore (found in the final end-to-end pass).

## Cloud sync (Supabase)

62. **Dexie stays the source of truth; sync sits under the repositories.** Every repository write stamps the
    record with `_mtime` and queues it in a `dirty` outbox table (Dexie v2), in the same transaction. Screens are
    unchanged. The sync engine pulls (merging record by record) and then pushes the outbox; an outbox entry is
    cleared only if the record didn't change again while the push ran.
63. **Cloud rows are `{id, user_id, data, updated_at, deleted_at}`** with the record in `data`. `updated_at` is
    *server* time set by a trigger and is only the pull cursor (device clocks don't matter for "what's new"). The
    conflict clock travels in `data._clock` and is compared in the app *and* in the database trigger, so an old
    device can never overwrite newer cloud data, even if two devices push at once.
64. **Conflict clocks:** notes, packages, settings: last write (`_mtime`). Cards: latest review first
    (max of `lastReview` and `resetAt`), then last write, as requested. `resetAt` is set when an edit resets a card
    and when a review is undone, so neither is overwritten by the older review state.
65. **Review logs and quiz results are append-only** (insert-if-absent; the trigger keeps `data` immutable).
    Undo is the one exception: it soft-deletes the log (`deleted_at`), and other devices drop it.
66. **Soft deletes only.** Trash syncs as the note's `deletedAt` (row `deleted_at` set). Permanent deletes sync as
    tombstones (`data._tombstone`, `deleted_at`). The database refuses DELETE/TRUNCATE for app users.
67. **First sign-in on a device is a merge:** everything local is queued, everything in the cloud is pulled, and
    each record is resolved by the rules above. Nothing local is dropped unless the cloud has a *newer* deletion.
68. **New card ids are deterministic** (`noteId:template`), so two devices that create a note's cards on their own
    (template migrations) produce the same ids. Older random-id twins are collapsed on pull: the version with the
    latest review wins and the other is deleted everywhere.
69. **Email OTP (6-digit code), not a magic link**: the installed PWA has separate storage from the browser, so a
    link would sign in the wrong one. The session is persisted in localStorage (`fluency-lab-auth`) and refreshed
    automatically. Sign-out is per device and keeps local data.
70. **supabase-js loads lazily** (only when a saved session exists or the user signs in): local-only users don't
    download it and nothing contacts Supabase.
71. **Sync triggers:** app start, `online`, back to the foreground (if >1 min since the last sync), end of each
    study session and quiz, 20 s after other local changes, every 5 minutes while visible, and "Sync now".
72. **Sync state is per account and per device** (`meta` key `sync:<userId>`): never exported in backups and kept
    when a backup "replace" wipes the data. A replace is itself synced: what's not in the backup is deleted in
    the cloud too (the user confirmed a replace).
73. **Only the publishable key ships in the client** (`src/sync/config.ts`); it's public by design. RLS
    (`auth.uid() = user_id`, `to authenticated`, `force row level security`, anon revoked) protects the data.
74. **Tests run the real schema in real Postgres** (PGlite, with Supabase's `auth.uid()` and roles stubbed):
    RLS isolation, no anon access, no hard deletes, newer-clock-wins and append-only triggers, plus two simulated
    devices syncing through it (first-login union, last-write-wins both orders, latest-review-wins for cards,
    offline then online, duplicate pushes, Trash / permanent delete / undo, edit resets, twin cards, account
    isolation, incremental pulls).
75. **Supabase sign-in is tested by the user, not by me**: signing in to a remote service with the user's email
    code is something only the user should do. Everything below sign-in is covered by the tests above.
